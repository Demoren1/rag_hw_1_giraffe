# Домашнее задание № 1. Доказательный RAG по ТФКП

Сделайте RAG: ответ по учебнику, краткое обоснование, ссылки на фрагменты. Модель — **[Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B)**. Работа индивидуальная. Дедлайн — в объявлении к заданию.

## 1. Материалы

Источник — [Горяйнов, Половинкин. «Лекции по ТФКП», 2025](https://new.mipt.ru/upload/mathematics/study/uchebniki/%D0%9B_%D0%A2%D0%A4%D0%9A%D0%9F_%D0%93%D0%BE%D1%80%D1%8F%D0%B9%D0%BD%D0%BE%D0%B2_%D0%9F%D0%BE%D0%BB%D0%BE%D0%B2%D0%B8%D0%BD%D0%BA%D0%B8%D0%BD_2025.pdf). Используйте только выданный корпус.

В комплекте:

- `corpus.jsonl` — текст, формулы, исходные `block_id`;
- `dev_questions.jsonl`, `dev_gold.jsonl` — открытые вопросы, ответы, допустимые наборы источников;
- `runtime.json` — ревизия модели, доступ, thinking, sampling, квантизация, RAM и тайм-ауты;
- пример API-запроса, простой RAG-baseline, скрипт проверки формата и оценки.

Строка корпуса: `block_id,page,section,text`. `page` — страница PDF с 1, не обязательно печатный номер. Делить и объединять текст можно; цитировать нужно исходные `block_id`. QA-примеры — в отдельном файле `tfkp_15_qa.md`.

## 2. Задача и эксперименты

Четыре категории: **условия теорем; сопоставление фрагментов и контрпримеры; короткие вычисления и выводы; недостаточность источника**.

В вопросе 4–6 вариантов, правильных может быть несколько. Выберите все правильные, обоснуйте, укажите источники. Допустим короткий вывод из нескольких фрагментов. Ответ из памяти без опоры на корпус не подходит.

Если оснований недостаточно — отказ. Если основания есть, но поиск их пропустил, отказ ошибочный. У разрешимого вопроса минимум один правильный вариант.

Реализуйте сборку индекса, поиск, контекст, структурированный ответ и отказ. Сравните **модель без контекста, RAG с одним поиском и одним вызовом LLM, итоговую систему**. Сделайте **две абляции**: отдельно отключите два существенных компонента. Неудачное улучшение допустимо — объясните результат. Вопросы и параметры LLM одинаковы во всех экспериментах.

Разрешены BM25, dense/hybrid retrieval, reranking, соседние фрагменты, декомпозиция, rewriting, повторный поиск; любые библиотеки или собственный код. Агент необязателен. Для адаптивного цикла логируйте решение, определившее следующее действие; фиксированная цепочка адаптивной не считается.

Публичные embedding-модели и негенеративные reranker-модели: **каждая ≤1 млрд параметров**, ревизии зафиксированы, ресурсы соответствуют `runtime.json`. Все генеративные шаги — только заданная Qwen. Запрещены дообучение, дистилляция сильной модели, генеративное обогащение корпуса и вызовы LLM при сборке индекса.

## 3. Форматы

Вход — JSONL, вопрос на строку:

```json
{"id":"q_001","question":"Текст вопроса","options":[{"id":"A","text":"Утверждение 1"},{"id":"B","text":"Утверждение 2"},{"id":"C","text":"Утверждение 3"},{"id":"D","text":"Утверждение 4"}]}
```

Категория, число правильных вариантов и эталоны скрыты. Порядок вариантов может меняться; используйте фактические ID.

Выход — ровно одна строка на входной `id`, без пропусков, дублей и лишних записей:

```json
{"id":"q_001","answer_ids":["A","C"],"abstain":false,"rationale":"Краткое обоснование","citations":["b_0042","b_0107"]}
```

- `answer_ids`: уникальные ID вариантов; порядок неважен.
- `abstain`: boolean. При отказе `true`, оба списка пусты; иначе `false`, оба непусты.
- `rationale`: непустое обоснование ≤1 200 символов, при отказе — причина. Полный внутренний ход рассуждений не нужен.
- `citations`: ≤4 уникальных исходных `block_id`, вместе подтверждающих ответ. Лишние ссылки снижают балл.

JSONL без Markdown; диагностические логи отдельно.

## 4. Запуск и лимиты

Чистое окружение, Python 3.11:

```bash
python -m pip install -r requirements.txt
python build_index.py --corpus /path/to/corpus.jsonl --output ./index --config config.json
python predict.py --index ./index --questions /path/to/questions.jsonl --output ./answers.jsonl --trace ./trace.jsonl --config config.json
```

Все файлы индекса — в `--output`. Предсказание без ручных действий. Сервер, бот и интерфейс не нужны; ноутбук команды не заменяет.

Генерация: OpenAI-совместимый Chat Completions API. Переменные: `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`. Заголовки каждого запроса: `X-Question-ID` = ID вопроса, `X-Submission-ID` = переменная `SUBMISSION_ID`. Проверяющие подставляют свой endpoint. Доступ для разработки описан в `runtime.json`; личный платный аккаунт не требуется.

На вопрос, включая rewrite, проверку и повторные попытки:

| Ограничение | Максимум |
| --- | ---: |
| Вызовы LLM | 4 |
| Входные токены суммарно | 16 384 |
| Выходные токены суммарно, включая thinking | 4 096 |
| Вход + допустимый выход одного запроса | 8 192 |

Параметры генерации из `runtime.json` менять нельзя. Поиск, embeddings и reranking — CPU; LLM работает отдельно.

Зависимости и заявленные модели скачиваются до прогона. При ответах сеть разрешена только для заданного endpoint. Запрещены внешние источники/API, заготовленные ответы по тексту/ID и перенос информации между вопросами. Неизменные индекс и веса можно переиспользовать.

`trace.jsonl`: строка на вопрос, поля `id,llm_calls,input_tokens,output_tokens,elapsed_ms,retrieved_block_ids`. Учитывайте все генеративные вызовы. Расход проверяется по журналу endpoint/прокси. Сборка индекса, загрузка весов и прогрев учитываются отдельно. Latency на балл не влияет.

## 5. Оценка

Для разрешимого вопроса: `A = 1` при точном наборе вариантов без отказа, иначе `0`. `F` — максимальный F1 ссылок среди допустимых эталонных наборов. Балл: `s = A × (0.8 + 0.2 × F)`.

Для недостаточности источника: `s = 1` за корректный отказ, иначе `0`. `Q` — среднее четырёх средних баллов по категориям.

```text
C_i = input_tokens_i + 4 × output_tokens_i + 256 × llm_calls_i
C = средняя C_i по всем вопросам
E = min(1, C_ref / max(C, 1))
Итог = 75 × Q + 25 × Q × E
```

`C_ref` — средняя стоимость выданного baseline на том же тесте и параметрах LLM. Это учебная стоимость, не тариф API. Параметры baseline фиксированы. Экономия ниже baseline множитель выше 1 не даёт.

Некорректная запись или превышение лимита: 0 за вопрос, он остаётся в знаменателе. Хотя бы одно превышение вычислительного лимита или отсутствие проверяемого расхода: **0 за эффективность всего прогона**.

Проверка — запуск на закрытом тесте, выборочная проверка обоснований, отчёта и абляций по общему правилу; спорные случаи отдельно. Содержательное противоречие в обосновании обнуляет вопрос с указанием причины. Возможна короткая защита.

В отчёте: формулы, чанкинг, поиск, контекст, отказы; таблица экспериментов и выводы двух абляций; три ошибки (вопрос, найденные фрагменты, причина); время сборки, пиковая RAM, размер индекса, оборудование; внешний код и помощь ИИ. Сданный код нужно уметь объяснить.

Столбцы CSV: `name,answer_accuracy,Q,mean_input_tokens,mean_output_tokens,mean_llm_calls,mean_cost,median_latency_ms`. Без контекста оценивайте правильность вариантов; `Q` оставьте пустым.

Авторские вопросы: по два на категорию, формат открытого набора. Эталоны: правильные варианты, допустимые блоки, обоснование; для двух отказов — недостающие сведения. В закрытый тест текущего потока они не входят.

Перед сдачей: пересоберите удалённый индекс; запустите из другой папки с другими путями; проверьте ID, ссылки, лимиты, состав и публичную доступность репозитория, совпадение конфигурации с экспериментами.
